# Каталог нормативов (Task 16 и Task 18)

Здесь приложение ищет снапшоты нормативов:

```
public/benchmarks/benchmarks-7.41.json      # Task 16: LH/золото/опыт на 15-й минуте
public/benchmarks/item-timings-7.41.json    # Task 18: тайминги покупки предметов
```

**В репозитории этих файлов нет** — они исключены из Git (`.gitignore`,
правило `/public/benchmarks/*.json`), потому что права на публичное
распространение производных данных OpenDota/Valve не подтверждены.

## Поведение без файлов

Приложение собирается и работает без снапшотов: запрос получает `404`, загрузчик
возвращает `null`, и на странице матча показывается состояние
«Нормативы недоступны: снапшот не загружен или не прошёл проверку»
(Task 16) либо таймлайн покупок без сравнения (Task 18).
Никакие статистические значения при этом не подставляются.

## Как включить нормативы локально

```powershell
# Task 16 (нормативы 00:00–15:00), из корня проекта
node scripts/build-benchmarks.mjs --patch=7.41
Move-Item src/data/benchmarks-7.41.json public/benchmarks/benchmarks-7.41.json

# Task 18 (тайминги покупки предметов) — пишет файл сразу в public/benchmarks/
node scripts/build-item-timings.mjs --patch=7.41
```

Генератор таймингов делает 4 запроса к OpenDota Explorer (диапазоны `hero_id`),
поэтому занимает несколько минут; `--dry-run` считает без записи, `--force`
разрешает перезапись существующего снапшота.

Снапшот таймингов содержит три порога выборки: `store = 30` (минимум наблюдений
для сохранения бакета), `full = 100` (показ квартилей) и `classify = 100`
(класс «раньше/типично/позже»). Приложение никогда не классифицирует тайминг
при выборке меньше 100 наблюдений, даже если в файле указан меньший порог.

## Как включить нормативы в публичном деплое

Только после того, как владелец подтвердит условия использования данных
(см. README, разделы «Нормативы первых 15 минут» и «Анализ покупки предметов»):

1. сгенерировать снапшот на доверенной машине;
2. включить файл в артефакт развёртывания (не в Git), либо загрузить его в
   хранилище, доступное приложению по тому же пути `/benchmarks/…`;
3. проверить, что приложение показывает нормативы и атрибуцию OpenDota.

**Важно:** Vite копирует содержимое `public/` в `dist/`. Локальная сборка
`npm run build` поэтому **включает** сгенерированные снапшоты в `dist/benchmarks/`.
Пока вопрос распространения данных не решён, каталог `dist/benchmarks/`
(или конкретные файлы) должен исключаться из публикуемого артефакта и не
загружаться на публичный хостинг.

Удаление файлов возвращает приложение в безопасное состояние «нет нормативов».
