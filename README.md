# DotaZ

## Обзор проекта

**DotaZ** — веб-сайт для анализа матчей Dota 2 по ID матча: пользователь вводит числовой ID матча и получает достоверную статистику, наблюдения с указанием источника данных и личную историю отчётов. Принцип продукта: не выдавать гипотезы за доказанные игровые ошибки.

Источники требований: `Product_brief.md` (продуктовый бриф), `ARCHITECTURE.md` (техническая спецификация MVP), `PLAN.md` (план реализации, Tasks 1–13), `AUDIT_REPORT.md` (отчёт аудита документации от 14.10.2026).

> **Текущее состояние репозитория (проверено 14.10.2026): исходного кода приложения ещё нет.**
> Репозиторий содержит только проектную документацию и один образец ответа OpenDota.
> Локально запустить приложение на данный момент **невозможно** — см. раздел
> «Известные проблемы и ограничения».

### Планируемый функционал (по документации, ещё не реализован)

- Регистрация, авторизация и подтверждение email через Supabase Auth.
- Валидация ID матча и загрузка данных из OpenDota `GET /api/matches/{match_id}`.
- Сводка матча, статистика десяти участников, выбор игрока.
- Наблюдения на основе фактических показателей; частичный отчёт при нехватке данных.
- Данные стадии линии 00:00–10:00 без оценочных выводов, пока не подтверждены нормы героя/роли.
- Приватная история отчётов: один отчёт на пару `(user_id, match_id)`, доступ только владельцу (RLS).
- Локализация интерфейса RU/EN.

### Функциональность, уже реализованная в репозитории

- Проектная документация: `PLAN.md`, `ARCHITECTURE.md`, `Product_brief.md`, `AUDIT_REPORT.md`.
- Образец данных OpenDota: `samples/match-.json`.
- Приложение (frontend/backend), маршруты, авторизация, интеграции с Supabase и OpenDota — **не реализованы**.

## Конфигурация окружения

Текущее состояние проекта **не требует переменных окружения** — исходного кода, читающего переменные окружения, нет.

Файл `.env.example` создан и намеренно содержит только комментарии (без переменных и без значений). Когда приложение начнёт использовать переменные окружения:

1. Скопируйте `.env.example` в `.env`.
2. Заполните значения локально.
3. Никогда не коммитьте `.env` — он исключён из Git через `.gitignore`.

Правила безопасности (по `PLAN.md`, правило 6, и `ARCHITECTURE.md`, п. 7):

- В Git не передавать `.env`, API-токены, ключи Supabase `service_role`, пароли и логи с секретами.
- Ключ `service_role` и секреты OpenDota не использовать в браузере; внешние запросы с секретами выполняются на доверенном сервере или Edge Function.

## Известные проблемы и ограничения

1. **Исходный код приложения отсутствует.** В репозитории только документация и образец данных. Локальный запуск невозможен — это основной блокер текущего этапа (Task 1). Создание приложения выполняется последующими задачами плана.
2. **Git-репозиторий не содержит ни одного коммита** (ветка `master`, все файлы не отслеживаются). Первый коммит выполняется владельцем проекта после проверки Task 1.
3. **Отсутствует файл `supabase/migrations/20261014_dotaz_initial.sql`**, который упоминается в `ARCHITECTURE.md` (п. 8) и `AUDIT_REPORT.md` как предоставленный пример миграции. В репозитории его нет; требуется решение владельца проекта.
4. **Имя файла `samples/match-.json` выглядит обрезанным** (ожидается вида `match-<id>.json`). Кроме того, `match_id` внутри файла (`9040229641`) не совпадает с тестовыми матчами из `Product_brief.md` (`9035016192`, `9007760151`). Переименование не выполнялось — вопрос к владельцу проекта.
5. **Образец `samples/match-.json` не содержит расширенных полей** (`lh_t`, `gold_t`, `xp_t`, `kills_log`, `deaths_log`, `purchase_log`, `lane_efficiency_pct`) — только базовые поля и `benchmarks`. Это подтверждает оговорку `ARCHITECTURE.md`: наличие расширенных полей не гарантировано для каждого матча.
6. **Политика выполнения PowerShell** на данной машине блокирует `npm.ps1`; для npm используйте `npm.cmd`.
7. **Автоматические проверки (build/test/lint) не выполнялись** — соответствующие команды отсутствуют. Браузерная проверка не выполнялась — проверять нечего.
